Same reader, two policies

        
Both panels run the same code: plan a grid, find the level, find the files, read only the blocks, sample into the screen tile. They differ only in the knobs above each map. The left panel copies deck.gl-raster's defaults; it is an emulation of those defaults, not deck.gl. The right panel uses the rules of a recipe reader, the policy of the REMA explorer. A third preset copies gdalwarp.

        
The knobs

        
Level of detail. deck.gl-raster selects the coarsest level whose source pixel is no larger than one device pixel. gdalwarp picks the overview closest to the output resolution but not coarser. A recipe reader takes the coarsest level whose pixel is no larger than 1.5 CSS pixels. On a 2x screen the first and last differ by a factor of 3, usually one or two pyramid levels, four to sixteen times the bytes. Here every rule is measured from the screen tile's footprint in the source CRS, which is the option (D) sketched in deck.gl-raster's own LOD notes.

        
Mosaic pyramid. deck.gl-raster's MosaicLayer opens every file in view and uses each file's own internal overviews. A VRT can declare <Overview> entries that cover the whole mosaic, so a continent is one coarse file, not thousands of headers.

        
Overview extent. GDAL assumes an overview covers exactly the base extent. Overviews built separately often do not. The recipe reader uses each file's own georeferencing.

        
Mesh error. Screen tiles are warped through a coarse grid of exact transforms; cells whose interpolation error exceeds 0.125 pixels are transformed exactly. deck.gl-raster and gdalwarp (-et) share that default, both in source pixels. Output pixels is the alternative deck.gl-raster added experimentally in #711. Source pixels over-refine when the level read is much finer than the screen. The count of exact transforms is in the log.

        
What is the same

        
Both read from the source in its own CRS, both draw through the same display CRS, both load from the centre outwards with six requests per host, both count every byte.
